# 設計：衛福部「真相說明」爬蟲

## 決策 1：以列表頁為唯一真相，明細頁只取內文

列表頁（`lp-4343-1-{page}-20.html`）已經提供標題、發布日期與連結三者。明細頁只用來取內文。

理由是日期。三個站的明細頁日期呈現各不相同：本部的明細頁內文裡有多個民國日期（事件發生日、函文日、公告日），抽到哪一個取決於正則寫法；國健署頁面同時有「發布日期」與「更新日期」且用西元格式；疾管署的頁面結構又是另一套。**列表頁的日期是同一個欄位、同一種格式（民國 `115-09-01`），跨三個站一致。**

用列表頁的日期，等於把「日期從哪來」這件事收斂成一個地方，而不是三個各自可能抽錯的解析器。

## 決策 2：依網域分派，`fda.gov.tw` 於列表階段即排除

真相說明是彙整頁，一筆條目可能連到四個不同機關的網站。分派表：

| 網域 | 處理 | 來源名 |
| --- | --- | --- |
| `mohw.gov.tw/cp-4343-*` | 解析 | 衛福部真相說明 |
| `hpa.gov.tw/Pages/Detail.aspx` | 解析 | 國健署真相與闢謠 |
| `cdc.gov.tw/Bulletin/Detail/*` | 解析 | 疾管署闢謠專區 |
| `fda.gov.tw` | **排除** | —— |
| 其他 | 排除並記 log | —— |

排除 `fda.gov.tw` 不是因為內容重複就好，而是因為**去重抓不到它**：ETL 以 `url` 字串為鍵，而真相說明上的食藥署連結是 `http://` + 小寫 `/tc/` + utm 參數，與 `scraper_fda` 產生的 `https://` + `/TC/` 不相等。跟著爬會讓同一篇存兩份，兩份各自佔用 embedding 額度、各自出現在檢索結果裡。

**未知網域一律排除並記 log**，不是靜默跳過：站方日後新增轉載機關時，log 是唯一會讓我們知道的訊號。

## 決策 3：三個來源名，不是一個

大可全部標成「衛福部真相說明」（它們確實都從那一頁來），但 `source_name` 是使用者在 CARE 回覆的參考來源清單裡看到的機構名。把國健署的文章標成衛福部，就是引用錯機關——而使用者點進連結會看到 `hpa.gov.tw`，兩者對不上。

這與本次一併修正的 `hpa.gov.tw` 誤標是同一條原則：**來源名必須與實際發布機關一致**。

代價是 `EXPECTED_SOURCES` 從 4 個變成 7 個，而 `find_missing_sources` 要求每個來源每次執行都要有產出。疾管署那 24 筆全部是 110 年的舊文，**日常增量不會有新的**——因此疾管署 SHALL NOT 列入 `EXPECTED_SOURCES`，否則每天都會誤報來源全滅。這是刻意的例外，不是遺漏。

## 決策 4：404 不得直接當成「文章已下架」

f8（另一個 session）在做 RAG 來源連結存活檢查時實測到：**`www.fda.gov.tw` 在被打快時會回假的 404，不是 429。** 同一個網址在全域併發 8 之下回 404，加上 per-host 節流後回 200，逐一間隔 2 秒手測三次全部 200。

本專案在同一批政府站台上已知的失效形式至少五種：

| 站台 | 已觀察到的失效 |
| --- | --- |
| `hpa.gov.tw` | SSLError（缺中繼憑證）、403（WAF）、ConnectTimeout |
| `fda.gov.tw` | 節流造成的假 404 |
| `cdc.gov.tw` | 偶發 TLS 握手失敗 |
| `mohw.gov.tw` | SSLError（缺中繼憑證） |

結論：**任何單次探測都不足以判定一篇文章消失了。** 本爬蟲因此不實作「404 就標記下架」的邏輯——抓不到就是本次跳過、記 log、下次再試。既有文件不因抓取失敗而被刪除。

## 決策 5：憑證用既有的 `ca_bundle`，不新增機制

`mohw.gov.tw` 與 `hpa.gov.tw` 都只送 leaf 憑證、不附中繼憑證 TWCA Secure SSL CA，Python 的 ssl 模組不會依 AIA 自動補抓。實測（2026-09-02）：

| 站台 | certifi | ca_bundle |
| --- | --- | --- |
| `mohw.gov.tw` | SSLError | 200 |
| `hpa.gov.tw` | SSLError | 200 |
| `fda.gov.tw` | 200 | 200 |

`ca_bundle.get_ca_bundle()` 已經解掉這件事，新爬蟲沿用即可，SHALL NOT 使用 `verify=False`。

## 決策 6：民國年於爬蟲端轉為西元

列表頁的日期是民國格式（`115-09-01`）。既有三個來源寫進 `published_at` 的都是西元格式，Tier 2 之類的下游會依這個欄位排序與比較。**在爬蟲端轉換**，讓寫進知識庫的格式維持單一。

三位數（含）以下視為民國年：西元年不可能是三位數，因此這個判準沒有歧義。

## 決策 7：來源名改名需要 migration，且必須先跑

`衛福部闢謠網站` → `國健署新聞` 是既有文件的欄位改名。若只改爬蟲不改既有文件，知識庫裡會同時存在兩個名字指向同一個來源，而使用者會在不同回覆裡看到不一致的機構名。

migration 只改 `source_name` 一個欄位，**不動 `chunk_content` 與 `embedding`**，因此既有向量不失效、不需要與 CARE 端協調 cutover。

## 已知風險與證據缺口

1. **疾管署的明細頁解析器尚未實作與驗證。** 其網址是不透明 id（`Bulletin/Detail/PmSCiSjM5YpCUxXqoS81RA`），頁面結構未探測。24 筆全部是 110 年 COVID 時期的舊文，主題偏疫情而非用藥。若解析成本過高，把它降為「排除並記 log」是可接受的收斂——但那要在實作時明確做決定並更新本文件，不是默默跳過。
2. **首次全量抓取的 embedding 額度尚未估算。** 810 篇 × 未知的平均 chunk 數。另一個 session 回報 `rag_retrieve` 觀察到 embedding 疑似被限流（單次 0.6s 到 94s 的肥尾），本專案用的是同一個 Gemini API，首次執行很可能需要跨數日完成。
3. **列表頁翻頁上限 52 是本次實測值**，站方增刪內容時會變。爬蟲 SHALL 以「連續數頁沒有新連結」為終止條件（比照 `scraper_fda`），SHALL NOT 寫死 52。
4. **`nodeid=126` 那 8 筆的專區名稱未確認**，本次與 `nodeid=127` 同樣歸為「國健署真相與闢謠」。若兩者實為不同專區，來源名會有小幅不精確。
